# choices 模块契约

## 职责

- 管理 Immersive Galgame System 选项浮窗。
- 支持选项组件 Mod 在选项浮窗页导入、导出、列表管理。
- 支持选项解析预设。
- 点击选项后必须写入酒馆输入框并触发发送按钮，不能绕过输入框直接创建消息。

- 检定建议表的「骰子命令」在点击时由 `dice-check.js` 判定：通过骰子系统公开 API `window.AcuDice` 查属性、掷骰，结果以 `<meta:检定结果>` 块随展示文本一起经输入框发送；不得触发骰子系统自带的发送（它绕过输入框）。骰子系统不可用或数据缺失时按原命令文本降级，禁止伪造骰点。

## 选项浮窗多来源（`option-sources.js`）

- 选项来源与优先级：选项表（`option-table.js`）有内容时以表为准，不与正文选项混用；表缺失或为空，且 `bridge.optionBubble.bodyFallback` 开启时，才读最新页面正文末尾的选项块。
- 正文兜底只认明确的选项块：必须是正文最末尾连续的、不少于 2 行的编号行（`1.` / `（1）` / `选项1：`）或符号行；符号列表要求块前一行带「选项 / 选择 / 你可以 / 接下来 / 怎么做」等提示，编号列表要求从 1 开始或带「选项」字样。正文中间的普通列表、从 2 开始的步骤列表一律不识别。识别前先剔除正文尾部的分隔线、HTML 注释、成对标签块（`<meta>` / `<status>` 等）、代码围栏与【】面板；提示行含「状态 / 面板 / 属性」或整块都是「名称：数值」的符号列表不算选项。
- 「使用物品」按钮（`optionBubble.itemButton`，默认开）：物品目录与背包页同源（`buildItemCatalog`），背包为空时不出现；动作为使用 / 交给<在场角色> / 查看，在场角色取自当前页立绘与同屏站位（排除主角），读不到时「交给…」把半句话填进输入框由用户补名。
- 常用行动（`optionBubble.quickActions`，默认空）：用户自己编辑，每行一条、最多 8 条，不内置词库；为空不显示。
- 三个来源产生的最终文本都走 `onOptionBubbleClick`：写入酒馆输入框并触发发送（`fill` 模式只填入），没有任何旁路。物品面板按 Esc 关闭；检定骰点只来自选项表的骰子命令，物品与常用行动不产生骰点。
- 任一来源有内容就正常显示浮窗，不再提示「未找到选项表」；所有来源都为空时才提示。设置写入时浅拷（`normalizeOptionBubble` 不改入参）。

## 原因

shujuku 有剧情推进功能，绕过输入框直接发送可能导致剧情推进不触发。
