# storage 模块契约

- 0.36.91：同一故障连续执行及实际 `observe` 重读共用三次预算，`repair.changed` 不重置次数；异常 cause 链里的 `recoveryStopped` 必须穿透外层，不能再开一轮。`passiveObservation` 仅用于宿主原消息回执的本地条件读取，不用于网络、编码或写入。空间不足达到次数后保留原 Promise/结果，停止写入；只有实际清理产生的 `storage-capacity-changed` 通知才能续存，普通配置通知无效。全局配置镜像自身的失败上传最多三次，待同步本机配置保留，真实新配置或网络恢复才开启新批次；同步器自管次数时读远端不叠加通用重读。

- 0.36.90：`recoverOperation` 的条件等待必须同时声明 `waitFor.message` 与 `canResume`；无恢复条件的失败返回 `recoveryStopped`，嵌套恢复原样传递，抛错仍沿原异常链交付。`observe` 实际重读，`repeatable: 'read'/'save'` 只用于可安全重做的读取、固定键保存及持有原结果的写入步骤，按退避主动恢复，不用于模型或出图。所有恢复状态通过订阅发布原因、等待对象和可选设置入口，视觉层呈现；取消或成功释放状态，明确失败可收起。提示只保留文案与入口，不保留完整结果、请求或图片字节。

- `recovery-exhausted` 表示原操作已用尽自身的自动处理次数并返回明确失败；各层恢复必须原样交付，不重新执行，也不再进入条件等待。它不是取消或成功，已完成的保存、聊天目标取消及只读恢复仍沿原规则处理。

## 原操作自动恢复（0.36.88 本地草稿）

`automatic-recovery.js` 保留输入与已完成步骤。继续执行须有实际修复进展或与该故障有关的条件变化；普通幂等本地操作最多允许一次没有修复证据的重试，写词和出图禁用这一次。错误措辞变化不重置次数，无关通知也不能导致付费请求重发。等待中的操作仍为未完成，不能报告成功。`operation-edits.js` 只将本次修改的字段应用到最新状态，未改字段保持最新值。取消信号与所有者销毁结束等待；恢复不能删除业务字段或返回伪造成功。预设修订推进不再直接拒绝本次保存。


`observe` 仅观察可重新读取的来源，读取实际成功后直接交付该结果；不用于重放模型、上传或发送正文等副作用。真实目标结束返回取消结果，不能再次作为待恢复的失败进入等待。宿主发送回执丢失时观察原消息，已发送正文不重复发送。

## 旧立绘迁移持久化（0.36.88 本地草稿）

- 多键迁移用 `sprite-migration-journal.js` 的 `igs:sprite-migration:pending` 先保存可回退旧值，逐键写后核验，全部完成后清日志。读取前恢复未完成迁移；失败保留日志，未知格式拒用。日志只允许桥配置、阅读模式和已知模式标定键，不参与配置文件镜像。该机制保护本机迁移与中断恢复，不提供跨设备同时写入的强事务。
- 普通写失败补偿旧值，静默不落盘同样报告失败。原图/图库不迁移字节，不触碰媒体数据库。
- 根库旧续画注记由 `spriteMigrationNotesPending` 保护唯一持久副本，只有 expression-notes 文件上传成功或确认相同版本才清设置副本；网络失败仍留在设置中。卡库注记继续随卡库持久化。


## 媒体重试与配置提交（v0.36.56）

- 全局配置写入相同值或删除不存在的键不标记修改、不安排上传。
- 设置镜像提供 `onUploaded` 回调，core 在真实配置提交或恢复后通知媒体层复查等待引用解除的候选；storage 不直接删除图片或实现回收逻辑。
- 占用诊断区分等待引用解除与实际失败；备份和回收保留原队列并由既有调度续接，不要求手动重试。

## 职责

- 0.36.88：预设快照还需保留生图草稿修订、默认升级基线与备份；归一化/保存失败不可默默清空当前项或自定义内容。运行时预设变更通知由 presets 发出，storage 不启动生成任务。
- 管理配置的 IndexedDB/localStorage 持久化；图片字节、Blob URL、迁移和删除日志归 `media`。
- 持久化本地背景、立绘、头像、预设、Mod 元信息和本地草稿。
- 提供容量统计、删除、迁移和坏数据回滚能力。
- 负责预设注册表快照的读写、归一化和坏数据回退，至少覆盖 `current`、`items`、`drafts` 和 `updatedAt`。

## 存储前缀

- IndexedDB：`vn`
- key 前缀：`vn:*`
- Blob URL 必须可重建，不作为唯一长期来源。
- `preset-store.js` 当前以 localStorage-compatible / memory adapter 固定契约，后续再替换为异步 IndexedDB adapter。
- `tavern-settings-file.js` 把全局配置键镜像到酒馆 `user/files/igs-settings.json`：启动时文件较新则写回本机，本机改动防抖上传；聊天内状态、日志、待审队列不进文件。新增全局配置键要加进它的白名单。

## 禁止

- 禁止把本地文件只存在内存里导致刷新丢失。
- 禁止坏预设覆盖当前启用项。
- 禁止把真实 API Key 明文导出到预设或资源包。

## 图片相关约束（v0.36.39）

- `igs-settings.json` v2 使用 `deletedKeys`；读取网络失败、500、坏 JSON 不得当作 404 上传覆盖。每次上传先读取远程，保留未在本机修改的键和远程删除标记；同源上传串行、请求与响应体均有期限，失败保留待同步状态。
- `igs-map-custom:*` 不再写入或由全局配置同步恢复。地图唯一权威备份是 `igs-map-records.json`；旧设置文件中的地图键由 map repository 在缺少该备份且没有删除标记时一次性迁移。
- 引用存储使用 `checked-storage-write.js` 校验写后读回并在失败时恢复旧值。导入的配置、预设和文件夹保存失败须先恢复旧引用，再回滚暂存图片；不得用原包图片 ID 覆盖本机同名记录。
- 媒体 WAL 与 GC 状态保存在 `igs-media-journal`，它们属于持久数据，不能随清图片缓存删除。参见 media 契约。

v0.36.41：占用说明读取中央缓存的 `backend/persistent/auxiliary`，显示实际启用的跨会话存储与辅助所有者用途、条目数和容量/作用范围。没有 IndexedDB 时显示仅中央内存，不再报告虚构的 192 MiB 本地缓存。64 MiB 指图片编码字节，不能解释为全部浏览器图片内存。

v0.36.43：占用说明同时展示辅助元数据估算与 16 MiB 总预算、每个所有者估算/字节预算、超预算次数和完整载入错误；明确标注估算，不冒充浏览器堆的精确测量。
