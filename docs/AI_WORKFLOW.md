# AI 协作与验证流程

## 目标

本仓库的自动化验证只使用脱敏 fixtures、fake host 和本地构建，不依赖真实 API key、私人聊天记录、真实用户数据库或本机绝对路径。

## 修改流程

1. 先读取根 `README.md`、`AGENTS.md`、相关模块 `CONTRACT.md` 和对应测试。
2. 跨模块修改先搜索入口、调用者、状态流和持久化边界，再修改完整调用链。
3. 文档、结构和 fixtures 修改至少运行结构/静态检查；运行逻辑修改运行相关测试和模拟测试；loader、dist 或发布链修改运行完整 `gate`。
4. 验证失败时记录真实命令、退出码和剩余风险，不把未运行项目写成通过。

## 真机调试与复验

模拟测试覆盖不到的酒馆宿主差异，才进入真实酒馆调试。优先使用浏览器 CDP 检查 loader、bundle、DOM、事件绑定和控制台错误；CDP 不可用时使用 F12 手动探针，并保留可复现步骤。真机测试不得把密钥、cookie、聊天内容或用户数据写入仓库。

远程 loader 只能在目标仓库已公开、`app/dist/` 已存在且地址经维护者确认后测试。真机验证通过前不创建版本 tag；若失败，先修复、升 patch、重新构建和复验。
